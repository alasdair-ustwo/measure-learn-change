Design system evals · 18 Nov 2026

Measure,learn,change

We asked an AI agent to build our Modal from its Figma file, three ways, and graded every result against the design spec. Contracts and an authoring skill took it from 81% to 98%.

No contracts, no skills 81% Just Figma. Runs scored 69–94%.
Contracts 96% Runs scored 92–98%.
Contracts + skill + standards 98% Runs scored 96–100%.

Mean spec conformance over 3 runs each, graded against 26 requirements from the Modal's Figma spec.

02Learn

Every run passed tests, typecheck and the Storybook build. The usual checks couldn't tell the setups apart. Grading against the spec could.

1/33/3

Contracts send the agent to the spec

Without contracts, only 1 of 3 runs read the written spec in Figma; the others built from screenshots. The run that never read it scored lowest, at 69%. A contract asks for usage rules and accessibility notes, so the agent goes looking for them.

0/33/3

Contracts bring the docs and the tests

No baseline run fully documented when to use the Modal and when not to, and only 1 of 3 tested its dialog behaviour properly. With contracts, all 3 did both: the contract asks for the usage guidance, and its checks set the bar for tests.

254 pts

The skill makes it repeatable

The spread between best and worst run shrank from 25 points to 4. Only with the skill and standards did every run get the exact width per viewport, an explicit viewport prop and 48px touch targets.

03Change

What we're doing differently because of it.

  1. Contract firstEvery new component starts with its contract. It's where most of the quality comes from: it sends the agent to the spec and its tests hold the result to it.
  2. Skill and standards for consistencyThey turn a good result into a repeatable one, for about 14¢ more per component.
  3. Grade against the design, not just the buildA green pipeline didn't separate these setups. Grading the code against the Figma spec did.
  4. Fix the standards where they fight the specOne rule asks for a prop called variant where the spec says viewport. The skill followed the spec and was marked down for it. The spec should win.
  5. Keep measuringRe-run with every new model and every change to the skill or standards. Next: more runs per setup, and specs that leave more to judgement.

Method: three runs per setup on the same commit, 18 November 2026. Builder Claude Sonnet 5.5 (headless Claude Code with read-only Figma access), grader Claude Opus 5.5 (no tools) against 26 requirements written from the Modal's Figma spec, and separately against the active rules in our component standards. Three runs is a small sample, and a model grader isn't perfectly consistent, so treat differences of a few points as directional.
